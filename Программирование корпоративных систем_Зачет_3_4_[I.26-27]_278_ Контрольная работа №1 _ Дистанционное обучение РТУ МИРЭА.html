Контрольная работа 1
Разработка консольной информационной системы на Java
Работа выполняется по вариантам в командах по 4 человека, защита проекта (по командам) - пояснение кода и ответы на вопросы

Распределение по вариантам

Контрольная работа выполняется командой из 4 человек. Каждая команда выбирает один вариант информационной системы.

Выбранный вариант является сквозным и используется этой же командой во всех последующих контрольных работах:

КР 1 -> КР 2 -> КР 3 -> КР 4
Порядок выбора варианта:

1. Собрать команду из 4 человек.
2. Открыть таблицу вариантов.
3. Выбрать свободный вариант.
4. Указать номер группы.
5. Вписать ФИО всех 4 участников команды.
6. Не изменять вариант, который уже занят другой командой.
Открыть таблицу вариантов
Важно. Предметная область и основная сущность системы определяются выбранным вариантом. Названия классов, таблиц, полей и бизнес-операций должны соответствовать предметной области конкретного варианта.

Общая задача

Необходимо разработать на языке Java консольную информационную систему в соответствии с выбранным вариантом.

Пользователь должен работать с системой через интерактивное консольное меню. Основные данные системы необходимо хранить в MySQL или PostgreSQL.

В приложении необходимо продемонстрировать применение объектно-ориентированного программирования, Java Collections Framework, обработки исключений, JDBC и многослойной архитектуры.

База данных и предметная модель, разработанные в КР 1, используются в дальнейших контрольных работах.
Часть 1

Структура приложения и работа с базой данных

Необходимо создать Java-проект и реализовать подключение к MySQL/PostgreSQL через JDBC.

Главное меню

Главное меню должно соответствовать предметной области варианта.

Пример для системы технической поддержки:

======================================== СИСТЕМА ТЕХНИЧЕСКОЙ ПОДДЕРЖКИ ======================================== 1. Пользователи
2. Заявки
3. Поиск
4. Фильтрация
5. Статистика
6. Экспорт данных
7. Вывести таблицы базы данных
0. Выход
Выберите действие: 

Для другого варианта названия пунктов меню необходимо изменить в соответствии с выбранной предметной областью.

После выполнения операции программа должна возвращаться в соответствующее меню. Программа не должна завершаться после выполнения одного действия.
Часть 2

Предметная модель и CRUD

В системе необходимо реализовать минимум две связанные сущности.

Одна из сущностей должна описывать пользователя системы, клиента, сотрудника, посетителя или другого участника предметной области.

Вторая сущность определяется выбранным вариантом.

Пример варианта Основная сущность
Техническая поддержка Заявка
Библиотека Выдача книги
Гостиница Бронирование
Медицинская клиника Запись на прием
Интернет-магазин Заказ

Полный список вариантов приведен в Google-таблице.

Для основной сущности необходимо реализовать

1. Создание записи.
2. Вывод всех записей.
3. Получение записи по ID.
4. Изменение записи.
5. Удаление записи.
6. Поиск записей.
7. Фильтрацию записей.
8. Сортировку записей.

Требование к enum

В предметной модели необходимо использовать минимум одно перечисление enum.

Например, для заявок технической поддержки:

public enum RequestStatus {
    NEW,
    IN_PROGRESS,
    DONE,
    CANCELLED
}

Для другого варианта необходимо разработать собственное перечисление, соответствующее предметной области.

Например:

public enum BookingStatus {
    CREATED,
    CONFIRMED,
    COMPLETED,
    CANCELLED
}
Часть 3

Бизнес-правила и обработка ошибок

Для выбранной предметной области команда должна определить и реализовать минимум 5 бизнес-правил.

Бизнес-правила должны быть реализованы в Java-коде, а не только в интерфейсе пользователя.

Пример бизнес-правил

1. Нельзя создать запись без обязательного названия.

2. Нельзя указать несуществующего пользователя.

3. Нельзя установить некорректный статус.

4. Нельзя выполнить запрещенный переход между статусами.

5. Нельзя сохранить объект с некорректными данными.

Некорректный ввод

Программа не должна аварийно завершаться при ошибках ввода пользователя.

Введите ID:
abc

Ошибка: ID должен быть целым числом.

Необходимо обрабатывать минимум:

- ввод текста вместо числа;
- отсутствие записи с указанным ID;
- нарушение бизнес-правил;
- ошибки подключения к базе данных;
- ошибки выполнения SQL-запросов.
Часть 4

Поиск, фильтрация, статистика и экспорт

Поиск

Необходимо реализовать минимум два способа поиска, соответствующих предметной области выбранного варианта.

Например:

- поиск по названию;
- поиск по описанию;
- поиск по пользователю;
- поиск по дате;
- поиск по категории.

Фильтрация

Необходимо реализовать минимум два фильтра.

Например:

- по статусу;
- по типу;
- по приоритету;
- по пользователю;
- по диапазону дат.

Сортировка

Необходимо реализовать минимум два способа сортировки.

Для части операций допускается и рекомендуется использовать Java Collections Framework и Stream API.

items.stream()
        .filter(item -> item.getStatus() == Status.NEW)
        .sorted(Comparator.comparing(Item::getCreatedAt))
        .toList();

Статистика

Необходимо реализовать отдельный пункт меню для вывода статистики системы.

Статистика должна содержать минимум 5 показателей.

Например:

Всего пользователей: 15 Всего записей: 48 Активных: 18 Завершенных: 15 Отмененных: 3 Записей высокой важности: 12

Экспорт данных

Необходимо реализовать экспорт основных данных системы из MySQL/PostgreSQL.

Основной формат: Excel .xlsx

Дополнительно допускается экспорт в .csv.

Требования к объектно-ориентированной структуре

Запрещено: реализовывать всю информационную систему внутри одного класса Main.

В проекте необходимо использовать:

- классы и объекты;
- инкапсуляцию;
- private-поля;
- конструкторы;
- методы;
- enum;
- минимум один интерфейс;
- полиморфизм;
- коллекции;
- собственные исключения.

Рекомендуемая структура

src/
└── main/
    └── java/
        └── ru.mirea.project/
            ├── Main.java
            │
            ├── model/
            │   ├── User.java
            │   ├── MainEntity.java
            │   └── Status.java
            │
            ├── repository/
            │   ├── UserRepository.java
            │   └── MainEntityRepository.java
            │
            ├── service/
            │   ├── UserService.java
            │   └── MainEntityService.java
            │
            ├── exception/
            │   ├── EntityNotFoundException.java
            │   └── BusinessException.java
            │
            └── util/
                ├── DatabaseManager.java
                └── ExcelExporter.java
Название MainEntity использовать буквально не нужно. Вместо него команда создает класс, соответствующий своему варианту: ServiceRequest, Booking, Order, Appointment и т.д.

Разделение программы по слоям

Console UI -> Service -> Repository / JDBC -> MySQL / PostgreSQL
Console UI - выводит меню, принимает данные пользователя.

Service - содержит бизнес-логику и проверки.

Repository - выполняет операции сохранения и чтения данных.

Database - хранит данные и обеспечивает ограничения.
SQL-запросы не должны находиться непосредственно в коде консольного меню.

Требования к JDBC

Все основные данные должны сохраняться в MySQL или PostgreSQL.

Необходимо использовать:

- JDBC;
- Connection;
- PreparedStatement;
- ResultSet;
- try-with-resources;
- параметризованные SQL-запросы.

Неправильно

String sql =
    "SELECT * FROM users WHERE email = '" + email + "'";

Правильно

String sql =
    "SELECT * FROM users WHERE email = ?";

PreparedStatement statement =
    connection.prepareStatement(sql);

statement.setString(1, email);

Требования к базе данных

База данных должна содержать минимум две связанные таблицы.

Структура таблиц должна соответствовать предметной области выбранного варианта.

Необходимо использовать:

- PRIMARY KEY;
- FOREIGN KEY;
- NOT NULL;
- UNIQUE;
- ограничения допустимых значений, где они необходимы.

Пример связи

main_entity.user_id -> users.id

Для конкретного варианта название внешнего ключа и связанной таблицы выбирается в соответствии с предметной областью.

Начальные тестовые данные

- минимум 5 пользователей или участников предметной области;

- минимум 10 записей основной сущности;

- минимум 3 различных значения статуса или категории;

- данные должны позволять продемонстрировать поиск, фильтрацию и сортировку.

Командная работа

Контрольная работа выполняется одной командой из 4 человек.

- одна команда выполняет один вариант;

- в команде должно быть 4 человека;

- команда использует один общий проект;

- все участники должны понимать архитектуру и код проекта;

- выбранный вариант сохраняется за командой для КР 2, КР 3 и КР 4.

Что необходимо представить на защиту

1. Исходный код Java-проекта.

2. Файл pom.xml.

3. SQL-скрипт создания базы данных.

4. ER-диаграмму базы данных.

5. Экспортированный Excel-файл.

6. Инструкцию по запуску программы.

7. Рабочее консольное приложение.

На защите необходимо уметь объяснить

- назначение основных классов;

- применение инкапсуляции;

- назначение интерфейсов;

- применение enum;

- применение полиморфизма;

- использование коллекций;

- обработку исключений;

- работу JDBC;

- отличие Statement от PreparedStatement;

- связи между таблицами;

- основные бизнес-правила;

- создание, изменение и удаление записей;

- поиск, фильтрацию и сортировку;

- экспорт данных.

Итог КР 1

В результате команда должна получить полноценный консольный вариант информационной системы для своей предметной области.

Console UI -> Service -> Repository / JDBC -> MySQL / PostgreSQL

Разработанная система далее последовательно расширяется:

КР 1: Console -> КР 2: JavaFX -> КР 3: Spring + REST API -> КР 4: Android

Предметная область и вариант команды при переходе к следующей контрольной работе не изменяются.
